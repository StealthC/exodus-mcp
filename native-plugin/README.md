# Native Exodus MCP bridge

`ExodusMcpPlugin` is the first native, read-only bridge for Exodus. It is a
persistent global extension that starts no network listener. When enabled, it
accepts only an authenticated request over one Windows named pipe and returns a
small status snapshot captured during extension initialization.

## Contract

Before starting Exodus, the launcher must set both variables:

```powershell
$env:EXODUS_MCP_PIPE_NAME = '\\.\pipe\exodus-mcp-example'
$env:EXODUS_MCP_CAPABILITY = '<unguessable capability generated by exodus-mcp>'
```

The Go server is the owner of the capability. It must connect locally and send
the UTF-8 request below; the plugin replies with one UTF-8 JSON status message
and closes the pipe.

```text
capability=<capability>\nmethod=status\n
```

The status response contains the bridge protocol version, plugin version,
lifecycle, whether the bridge was enabled, and the number of modules observed
while Exodus initialized the extension. It does not expose memory, ROM bytes,
input, frame control, or scripting.

## Build

Use the supported Visual Studio 2022/v143 environment and build the Exodus SDK
dependencies first. The project intentionally imports Exodus's existing plugin
property sheets, so provide the Exodus root as `SolutionDir`:

```powershell
msbuild native-plugin\ExodusMcpPlugin.vcxproj /p:Configuration=Debug /p:Platform=x64 /p:SolutionDir="$PWD\vendor\exodus\"
```

Copy the resulting DLL into the Exodus extensions location used by the local
installation, then configure it as the persistent global extension
`Global.ExodusMcp`. Keep the Exodus MIT license notice when distributing an
Exodus-derived binary.

## Next bridge increment

The Go process must add the named-pipe client and startup launcher. Only then
should `bridge_status` report a live connection. Read-only commands must be
scheduled onto the Exodus emulation thread before accessing mutable emulator
state.
